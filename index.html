What an llms.txt file is for

      
An AI agent reading your site sees navigation, cookie banners and scripts before it sees your documentation. llms.txt is a small Markdown file at the site root that gives the agent a clean map instead: what the site is, and which Markdown pages are worth fetching.

      

        

          
The structure

          
    
            
  • One # H1 with the project or site name — the only required part
    • 
            
  • A > blockquote summary in a single line
    • 
            
  • Optional prose: base URL, auth, conventions
    • 
            
  • ## H2 sections, each a list of - [name](url): note
    • 
            
  • An optional ## Optional section for links an agent can skip
    • 
          

        

        

          
What this generator checks

          
    
            
  • The H1 exists and carries no second #
    • 
            
  • The summary is present and collapses to one line
    • 
            
  • Every URL is absolute, http(s) and free of spaces or broken brackets
    • 
            
  • Every link has a name, and every named section has links
    • 
            
  • Repeated URLs, overlong notes and stray headings are flagged
    • 
          

        

      

      
llms.txt complements robots.txt and sitemap.xml; it does not replace either. Where several files apply, an agent should use the most specific one — /docs/llms.txt covers everything under /docs/.

Questions

      

        

          How is the monthly cost calculated?
          
Each request is priced in three parts: fresh input at the input rate, the cached share of the input at the cached-input rate, and output at the output rate. Prices are per million tokens, so the sum is divided by one million. Multiply by requests per day and days per month for the month, and by twelve for the year.

        

        

          Are these the real list prices?
          
They were copied from each provider's public pricing page on 20 November 2026 and every field is editable, so you can enter a contract rate or a price change. Legacy models keep their last published list price and are hidden unless you ask for them. Confirm billing-critical numbers with the provider.

        

        

          What is a cached input token?
          
Providers let you reuse a prompt prefix that was sent recently — a system prompt, a document, a tool schema — and charge less when those tokens hit the cache. Enter the share of your input that repeats; 0% prices everything as fresh input.

        

        

          How accurate is the token estimate?
          
It uses the usual English rule of thumb: about four characters or 0.75 words per token. It is a planning aid, not a bill. Tokenizers differ by model, and the newer Claude tokenizer produces roughly 30% more tokens for the same text, so check a provider-side counter for anything billing-critical.

        

        

          Is my data uploaded anywhere?
          
No. There is no backend, no analytics, no third-party script and no web font from a CDN. The calculations and the file generation run in the tab, and the page keeps working offline after it has loaded.

        

        

          What is the difference between llms.txt and llms-full.txt?
          
llms.txt is the small index: an agent reads it, then fetches only the pages it needs. llms-full.txt is the expanded variant that carries the documentation text itself, so one fetch is enough. This generator keeps section bodies out of llms.txt and includes them in llms-full.txt.

        

        

          Where do I put the file?
          
At the root of the domain as /llms.txt, or at any subpath to cover just those pages, such as /docs/llms.txt. You can point at it with a rel="describedby" link or an HTTP Link: header. The file must be served as text; the download here is already a plain .txt.

        

        

          Does llms.txt replace robots.txt or sitemap.xml?
          
No. robots.txt says which crawlers may fetch what, sitemap.xml lists pages for search engines, and llms.txt guides an agent that is already allowed in. Most sites want all three.

        

        

          Why does the validator reject relative URLs?
          
Because an agent reads the file from outside your site and cannot resolve /docs/api against a base it does not know. Absolute URLs, ideally the Markdown version of each page, are unambiguous.

        

        

          Can I use this for a client site?
          
Yes. There is nothing to sign up for, no attribution requirement and no markup on your prices. The generated file is yours.
